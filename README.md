## Interactive dashboards — simulated data

Four five-page dashboards with dimensional models, automated KPI pipelines, filters,
drill-through and a governed KPI register on every one.

**These run on simulated data, deliberately.** Nobody publishes their real order-to-cash
ledger, HR records or cost-centre budgets. To demonstrate dimensional modelling and KPI
governance at realistic scale, the datasets are generated by the scripts in `pipeline/` —
a coherent multinational operator, modelled properly. They are evidence of engineering and
modelling; the analytical judgement is in the eight real-data analyses above.

### 1. Order-to-Cash Operations
50,000 orders, 500 customers, 27 countries. Tracks US$17.1B of order value through the full
cycle — ordered, delivered, invoiced, collected.

**Finding:** US$1.7B of order value is stuck (9.3% of all orders), half of it in APAC credit
holds. DSO runs 57 days against a 45-day target.

### 2. Supply Chain & Inventory
US$197M of inventory across 8 terminals and 25 suppliers.

**Finding:** two separate problems with two different fixes. A US$10.9M stockout problem
traces to 4 unreliable suppliers; a US$38.8M dead-stock problem traces to oversized minimum
order quantities.

### 3. Workforce & Safety
~1,000 employees across 12 sites.

**Finding:** frontline roles lose 35% of new hires within their first year, against 7% in
corporate roles — concentrated at two specific terminals. Those same two terminals carry the
network's highest recordable incident rate, because constant churn keeps them staffed with
inexperienced workers. The attrition problem and the safety problem are the same problem.

### 4. FP&A · Cost & Budget
US$191M of budget across 60 cost-center/site combinations.

**Finding:** company-wide opex sits within 0.7% of budget, which looks healthy and hides the
real issue. Labour costs at the same two terminals flagged above run 37% over budget, and are
getting worse each year (+17% → +37% → +58%). A separate finding: Infrastructure capex projects
finish on time only 31% of the time, versus 100% for Equipment and IT Systems, leaving US$8.9M
of approved capital unspent.

## How it's built

```
Excel star schema  →  Python pipeline  →  data.js  →  static dashboard
   (7 tables)          (computes KPIs)              (renders in browser)
```

Each project follows the same shape:

1. **Generate** — a script simulates three years of operational data with realistic patterns
   deliberately embedded, so there is something genuine to find.
2. **Model** — a 7-table star schema, dimensions and facts with proper keys. Loads cleanly
   into any SQL warehouse or BI tool.
3. **Compute** — a pipeline script reads the tables, computes every governed KPI, and writes
   a single compact JavaScript payload.
4. **Serve** — the dashboard renders that payload in the browser. No server, no database,
   no build step.

KPI definitions live in a register on page 5 of each dashboard: the formula, the source
tables, the target, the current value, and the owner. Methodology follows standard
conventions — DSO excludes disputed receivables, DIO uses a trailing 90-day window, TRIR and
LTIFR use the 200,000-hour convention.

The site folder is named `docs/` because GitHub Pages serves from either the repository
root or a folder with that exact name — it keeps the published site separate from the
pipeline code with no build step or deploy workflow needed.

## Running it locally

The site needs nothing installed — clone the repo and open `docs/index.html` in a browser.
It works offline.

To regenerate a dataset and rebuild a dashboard's data:

```bash
pip install pandas numpy openpyxl faker
python pipeline/generate_o2c_dataset.py       # regenerates the star schema into data/
python pipeline/build_dashboard_data.py       # rewrites docs/assets/data.js
```

The generators are seeded, so regeneration is deterministic — rerunning
`generate_o2c_dataset.py` reproduces the committed tables exactly, down to the
US$17,099,387,449.50 order value the dashboard reports. The build script reads either
`.xlsx` or `.csv` source tables, so the committed Excel snapshot and a freshly generated
CSV set are interchangeable.

Swap in different source tables, rerun the build script, reload the page — the dashboard
reflects the new data with no manual editing.

## A note on the data

Every dataset here is synthetic, generated by the scripts in `pipeline/`. No real company
data appears anywhere in this repository, and the site says so on every page.

What is real is the method: the dimensional modelling, the KPI governance, the defensible
metric definitions, and a reproducible path from raw tables to a published dashboard. The
findings above are genuine analytical results — the generators embed realistic patterns and
the pipelines surface them; the numbers were verified independently against the source tables
rather than asserted.
